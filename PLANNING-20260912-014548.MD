Tanggal: 2026-09-12 01:45 WIB | Baseline: tourandtravel (PHP 8.3, Midtrans, Duffel, points/tier, price_calendar, social-proof, wishlist polymorphic — semua SUDAH ada)

## FASE 1 — OAuth Social Login (1-2 hari, ROI tertinggi)
Masalah: hanya email+password → drop-off register besar.
- Tambah kolom: `users.google_id, avatar_url` (migrate `migrate-oauth.sql`).
- `login.php` + `register.php`: tombol "Login dengan Google" (Google Identity Services JS).
- `api/oauth-google.php` baru: verifikasi id_token via `https://oauth2.googleapis.com/tokeninfo`, cocokkan email → login/buat user → `$_SESSION`.
- `includes/auth.php`: helper `loginUser($id)` dipakai ulang.
- Test: E2E `tests/e2e/oauth-login.spec.ts` (mock token) + unit verifikasi email match.
- Done: register <10 detik, user lama ter-link by email.

## FASE 2 — Real-time Availability Engine (2-3 hari)
Masalah: booking manual confirm → risiko overbooking.
- Tambah `price_calendar.slots_booked` + kolom `tour_date_id.quota, booked`.
- `webhook-midtrans.php` + `ajax/create-payment.php`: saat `settlement/capture` → `slots_booked += pax` dalam transaksi DB; gagal bayar → rollback.
- `tour-detail.php`, `hotel-detail.php`: slot 0 = tombol disabled "Penuh".
- Test: unit `AvailabilityDeductTest.php` (double-settlement idempotent), E2E overbooking sad-path.
- Done: tidak ada overbooking walau 2 user checkout bersamaan.

## FASE 3 — Refund Self-Service (2 hari)
Masalah: hanya tombol "Batalkan" tanpa policy/tracking.
- Migrate `bookings.refund_status, refund_amount, refund_reason`.
- Policy engine di `includes/refund.php` baru: full (>H-7), 50% (H-3–H-7), non-refundable (<H-3) — per-produk via kolom `tours.refund_policy`.
- `my-bookings.php`: tombol "Minta Refund" + status tracking (diajukan→disetujui→dana kembali ke wallet).
- `admin/bookings.php`: approve/reject + auto-kredit via `includes/wallet.php`.
- Test: unit policy matrix + E2E refund flow.
- Done: user bisa refund mandiri, admin 1-klik approve.

## FASE 4 — Travel Insurance Add-on (1-2 hari)
Masalah: margin hilang, kompetitor selalu tawarkan di checkout.
- Migrate: `booking_addons` (booking_id, type='insurance', amount).
- Flat-rate internal dulu: 3% × total (tanpa API eksternal) — file `includes/insurance.php` baru, premi dihitung di `tour-detail.php` checkout + checkbox.
- Klaim manual via CS (cukup halaman syarat di `faq.php`).
- Test: unit premi 3%, E2E checkbox menambah total.
- Done: AOV +3%, fondasi ganti ke API Chubb/AXA nanti.

## FASE 5 — Bundle Flight+Hotel (2-3 hari)
Masalah: tidak ada cross-sell → AOV rendah.
- `includes/bundle.php` baru: `getBundleDiscount()` — diskon 5% jika booking flight+hotel dalam 24 jam (cek by user_id).
- `booking-success.php`: tampilkan "Lengkapi bundlemu, hemat 5%" + kupon otomatis via `admin/promo-codes.php`.
- Test: unit bundle window 24 jam, E2E cross-sell banner.
- Done: AOV naik, kupon bundle ter-track.
